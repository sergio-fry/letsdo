## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Во время выполнения агента выводятся строки действий (запуск инструмента, завершение, прочие служебные события). Перед каждой такой строкой выводить префикс времени HH:MM:SS, чтобы было видно, как давно произошло последнее действие (интервалы между действиями). Решение о том, куда идут служебные строки (stderr/отдельный поток) и как это сочетается с чистым выводом текста агента (TASK-9), принимает исполнитель — результат должен не конфликтовать с требованием «только строки агента» в stdout.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Каждая строка-действие логируется с префиксом HH:MM:SS (часы:минуты:секунды)
- [x] #2 По префиксам можно оценить интервалы между действиями (давность последнего)
- [x] #3 Формат префикса единый для всех действий
- [x] #4 Префиксы HH:MM:SS применяются к строкам-действиям и сочетаются с показом параметров/результатов инструментов (актуальный TASK-9) — общий аккуратный формат
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. OutputStreamer: единый префикс HH:MM:SS перед каждой строкой-действием в stderr (инжектируемые часы для детерминированных тестов); время берётся локальное, формат строго HH:MM:SS.
2. Строки-действия: запуск инструмента — 'HH:MM:SS ⚙ имя: параметры'; завершение — маркер 'HH:MM:SS ✓ имя: завершено (Xs)' / ошибка 'HH:MM:SS ✖ имя: ошибка (Xs)' после блока результата. Строки результата (данные) — без префикса, с отступом (это не действия; 'только строки агента' в stdout не трогаем — TASK-9).
3. Интервалы между действиями видны по разнице префиксов; длительность инструмента — по разнице времени запуска и завершения.
4. PiRunner: tool_result вызывается всегда (даже при пустом результате), передаёт имя инструмента.
5. Тесты: обновить существующие (учёт префикса), добавить проверки формата префикса, единого вида, маркера завершения с длительностью, пустого результата, отсутствия префикса у text_delta/stdout.
6. README: описание формата служебных строк. Прогон rake test.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Реализовано. Формат: каждая строка-действие в stderr пишется с единым префиксом HH:MM:SS (источник времени инжектируется clock: для детерминированных тестов). Запуск инструмента — 'HH:MM:SS ⚙ имя: параметры'; завершение — 'HH:MM:SS ✓ имя: завершено (Xs)' / 'HH:MM:SS ✖ имя: ошибка (Xs)' после блока результата. Строки результата (данные) — блоком с отступом без префикса времени. stdout — только текст агента (TASK-9 не затронут); служебное — в stderr. PiRunner передаёт имя инструмента в tool_result и печатает завершение всегда (даже при пустом результате). Валидация: rake test — 61 runs, 165 assertions, 0 failures; ручной прогон показал '20:25:11 ⚙ bash: ls -la', '20:25:11 ✓ bash: завершено (0.3s)', '20:25:11 ✖ bash: ошибка (0.1s)'.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Добавлены временные префиксы HH:MM:SS у строк-действий: OutputStreamer пишет запуск инструмента 'HH:MM:SS ⚙ имя: параметры' и завершение 'HH:MM:SS ✓/✖ имя: … (Xs)' (длительность = разница префиксов, интервалы между действиями видны по префиксам). Строки результата остаются блоком с отступом без префикса — формат аккуратно сочетается с показом параметров/результатов (TASK-9); stdout по-прежнему только текст агента. PiRunner передаёт имя инструмента в tool_result и печатает завершение при любом результате. Час источник инжектируется (clock:) для детерминированных тестов. Проверено: rake test — 61 runs, 165 assertions, 0 failures; ручной прогон показал '20:25:11 ⚙ bash: ls -la', '20:25:11 ✓ bash: завершено (0.3s)', '20:25:11 ✖ bash: ошибка (0.1s)'.
