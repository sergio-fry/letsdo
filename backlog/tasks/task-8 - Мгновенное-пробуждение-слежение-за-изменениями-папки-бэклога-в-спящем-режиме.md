## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Оптимизация режима ожидания: вместо опроса каждые 10 секунд следить за файлами бэклога на диске (backlog хранит задачи файлами — backlog/tasks и связанные файлы). Появление/изменение файлов — сигнал немедленно проверить, нет ли задачи для этого агента. Цель: быстрее подхватывать новые задачи и не жечь ресурсы частыми опросами.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Новая/изменённая задача в папке бэклога обнаруживается быстрее, чем за 10-секундный цикл ожидания (порядка 1-3 секунд)
- [x] #2 В отсутствие изменений цифра опросов минимальна (файловая подписка/редкий замер, без активного опроса каждые ~100мс)
- [x] #3 Собственные изменения бэклога циклом (агент закрыл задачу) не вызывают ложного рестарта или зацикливания
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Заменить ожидание по таймеру в bin/agent-loop на файловый вотчер: inotify через питоновский ctypes (без внешних зависимостей; inotifywait/модуля inotify нет на машине). Рекурсивные подписки на все каталоги backlog/ кроме .locks (список задач его не трогает — проверено; .locks исключён, чтобы свои же записи не будили цикл).
2. В режиме ожидания — блокирующий select(inotify_fd) с коротким таймаутом (~0.3 c): события файлов будят цикл мгновенно, таймаут сохраняет отзывчивость к SIGINT/SIGTERM (проверка stopped между select).
3. Анти-зацикливание (AC #3): повторная проверка pending_tasks() не чаще раза в 0.5 c (debounce); backlog task list — read-only и событий не порождает (проверено замерами mtime), события от собственных правок агента просто сбрасываются в буфере и приводят к одной лишней перепроверке без запуска агента, если задач нет.
4. Fallback: если inotify недоступен — прежний периодический опрос с AGENT_WAIT_SECONDS.
5. Новые подкаталоги в backlog/ добавляются в подписку по событию IN_ISDIR/при пробуждении.
6. Тесты: e2e — запуск agent-loop в фоне с AGENT_CMD-заглушкой, создание тестовой задачи через backlog CLI, замер задержки пробуждения, пометка задачи Done, проверка отсутствия повторных запусков; fallback-режим на smoke.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Реализация: inotify через ctypes (без внешних зависимостей; inotifywait/модуля inotify на машине нет). Рекурсивные подписки на все каталоги backlog/ кроме .locks (backlog task list read-only — события не порождает, проверено замерами mtime). Ожидание — блокирующий select(fd) с таймаутом 0.3 c (реакция на сигналы). События лишь инициируют перепроверку pending_tasks; без открытых задач агент не запускается → свои правки (агент закрыл задачу) не дают ложного рестарта. Новые подкаталоги подхватываются через _refresh_watches по событию. Fallback при недоступности inotify — прежний опрос AGENT_WAIT_SECONDS.

Валидация (e2e + unit):
- e2e фаза B: задержка create-задачи → прогон агента 644 ms и 753 ms (AC#1, <3 c); переназначение -a → 315 ms
- e2e простой: stderr 5→5 строк за 3 c, CPU 0 тиков за 3 c (нет опроса, AC#2)
- e2e фаза C: правки Done-задачи (2 комментария) → прогонов 3→3, ложного рестарта нет (AC#3)
- e2e2: задача другому агенту → 0 лишних прогонов
- unit: fallback (inotify недоступен) спит fallback_interval и возвращает True; новые подпапки подписываются; .locks исключён
- bash -n и python3 -m py_compile — без ошибок
Тестовые задачи на хендле @testagent (TASK-23..30) помечены Done, как прецедент TASK-18/19.
