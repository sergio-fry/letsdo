## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Сейчас bin/agent запускает агента один раз и завершается. Нужен цикл: агент берёт задачу, назначенную на его assignee-хендл, выполняет её до терминального статуса, затем переходит к следующей — и так, пока задачи есть. Остановка цикла — только внешняя (SIGINT/SIGTERM, clean exit). Работает для любого агента из .agents/: соответствие имени агента и assignee-хендла задаётся одним правилом (например developer → @developer).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 При N задачах в To Do, назначенных на агента, одним запуском цикла выполняются все N последовательно

- [x] #3 Цикл корректно завершается по SIGINT/SIGTERM с понятным сообщением
- [x] #4 Правило соответствия имя агента → assignee-хендл вынесено в одно место (developer → @developer)

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Новый скрипт bin/agent-loop <имя> (bash-обёртка + python, как bin/agent): бесконечный цикл оркестратора.
2. Правило имя->хендл одним правилом: handle='@' + имя, переопределение через AGENT_ASSIGNEE_HANDLE; доступность промпта .agents/<имя>.md проверяется на старте.
3. Проверка открытых задач: backlog task list --assignee <handle> --exclude-status Done --json; при наличии задач — один прогон bin/agent <имя> (один прогон = одна задача, выбор задачи на стороне агента), после выхода — повторная проверка (все N задач делаются за один запуск цикла).
4. При отсутствии задач — спящий режим: пауза (AGENT_WAIT_SECONDS, по умолчанию 10) и повторная проверка; цикл сам не завершается.
5. SIGINT/SIGTERM — чистый выход: обработчик ставит флаг, текущий прогон агента завершается (killpg всей группы процессов), exit 0. Ненулевой rc агента — предупреждение в stderr, цикл продолжается.
6. Команда прогона переопределяется AGENT_CMD (для тестов). Проверка: mock-агент + временные задачи @looptest — все N выполнены последовательно за один запуск, затем цикл в режиме ожидания; SIGTERM -> exit 0; уборка тестовых задач.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Верификация (все 4 AC подтверждены объективными прогонами):
1) N=3 тестовых задач @looptest + mock-агент (AGENT_CMD=/tmp/mock-agent.sh): за один запуск цикла все 3 выполнены последовательно (лог: 'открытых задач: 3/2/1, запускаю looptest', TASK-14→15→16 Done), затем переход в ожидание.
2) Режим ожидания: после выполнения задач лог 'задач нет, жду 1s' (AGENT_WAIT_SECONDS=1), процесс остаётся живым (ps) и повторяет проверки — не падает, не умирает. По умолчанию 10s.
3) SIGTERM в ожидании: exit 0 + '[agent-loop] остановлен'. SIGINT в ожидании: exit 0 + то же сообщение. SIGTERM посреди прогона агента: группа агента добивается (killpg, 'завершился с кодом -15'), цикл чисто останавливается, exit 0, висящих процессов нет.
4) Правило имя→хендл одним выражением в bin/agent-loop: handle = AGENT_ASSIGNEE_HANDLE или '@'+имя (developer → @developer).
Неизвестный агент: 'Неизвестный агент: <имя>' + usage, exit 1. Ненулевой rc агента: предупреждение в stderr, цикл продолжается.
Замечание: часть функциональности TASK-7 (пауза ожидания ~10s) уже реализована в TASK-6 — при планировании TASK-7 стоит учесть.
